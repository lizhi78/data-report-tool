# 数据分析报告生成工具

自动完成脏数据读取、清洗统计、异常识别，调用 AI 生成业务分析，输出 Excel 结果与 Markdown 报告。

## 项目功能

- F1：读取 CSV / Excel 原始数据文件
- F2‑F3：数据清洗，处理空格、千分位、单位、缺失、重复，输出清洗日志
- F4：数据描述统计、分组汇总统计
- F5：识别并标记业务异常数据
- F6：调用大模型 API 自动生成业务分析文本
- F7：导出多 sheet 清洗结果 Excel
- F8：输出完整 Markdown 分析报告
- F9：命令行传参运行，不硬编码文件路径

## 环境部署

### 1. 获取项目

拿到完整项目文件夹，终端切换到项目根目录 `data-report-tool`

### 2. 安装第三方依赖

```
pip install -r requirements.txt
```

### 3. 配置 API 密钥

根目录已存在 `.env` 文件，在里面填入自己的密钥

```
DEEPSEEK_API_KEY="填入你的密钥"
```

> 
> ⚠️ `.env` 已经配置在 `.gitignore`，**禁止提交到 git 仓库**，防止密钥泄露。

## 使用方式

### 命令行运行

```
python main.py --input 你的数据文件.csv --output ./output
```

参数说明

- `--input`：必填，原始脏数据路径，支持`.csv`、`.xlsx`
- `--output`：必填，输出文件存放目录，本项目默认使用`./output`

示例(如何使用)

```
python 流水线数据清洗/main.py -i ./流水线数据清洗/实习练习-销售脏数据.csv -o ./output/
```
输出结果示例：[text(markdown)](../output/汇总_实习练习-销售脏数据.md)
[text(excel)](../output/汇总_实习练习-销售脏数据.xlsx)



程序执行完毕，清洗后的 Excel、md 报告全部生成在 `output` 文件夹。

## 异常数据判定标准

本项目对销售明细中的 **数量**、**单价(元)**、**销售额** 三列进行异常标记。  
异常行会被标记为 `"异常"`，正常行则重新计算销售额。

### 判定规则（满足任意一条即视为异常）

| 规则 | 条件 | 判定理由 |
|------|------|---------|
| **数量过大** | `数量 > 1000` | 单笔销售超过 1000 件，远超常规零售场景，大概率是**录入时多写了一位**（如把 `100` 写成 `1000`），也可能是未经说明的批发/团购单。为避免对整体统计产生极端拉偏，先标记为异常，人工复核后再决定是否保留。 |
| **数量无效** | `数量 <= 0` | 包括 **0** 和 **负数**。 `0` 表示没有实际成交，属于无效记录；负数通常意味着**退货**或**冲红**，但在原始销售表中未与正常销售区分，直接参与求和会导致总额虚减。因此统一标记为异常，后续可单独做退货分析。 |
| **单价无效** | `单价(元) <= 0` | 单价为 0 或负数，意味着**免费赠送**、**试用**或**数据缺失**。这类记录不产生实际销售收入，若混入正常销售统计，会拉低平均客单价和总销售额，故标记为异常。 |

### 异常行的处理方式

1. **正常行**（以上三条均不满足）：
   - 重新计算销售额：`销售额 = 数量 × 单价(元)`
   - 确保销售额与数量、单价保持逻辑一致

2. **异常行**（满足任意一条）：
   - `数量`、`单价(元)`、`销售额` 三列统一标记为 `"异常"`
   - **原销售额备份到新增的 `销售额_previous` 列，方便追溯原始数据**

### 为什么这样定？

- **不直接删除**：原始数据需要保留备查，删除后无法追溯。
- **不自动修正**：异常原因多样（录入错误、退货、赠品），程序无法判断真实意图，标记后交由业务人员复核。
- **三列同时标异常**：只要数量或单价任一异常，销售额就失去了计算意义，因此三列统一标记，避免"部分正常、部分异常"造成的误解。
